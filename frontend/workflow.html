START

Entry Point
Description

The entry point of the LangGraph workflow. This is where execution begins when a test case is triggered or a standalone command is issued.

Connections
→ check_resume
↻

check_resume

Utility Node
Description

Checks if the current invocation is a resumption from a Human-in-the-Loop (HITL) intervention. If HITL state exists, routes to apply_guidance. Otherwise, proceeds to detect_mode.

State Checked

state.hitl_pending, state.human_guidance

Connections
← START
→ detect_mode (normal)
→ apply_guidance (HITL resume)
⚙

detect_mode

Utility Node
Description

Determines the execution mode based on input state. Routes to TEST_EXECUTION if test_id exists, STANDALONE if command exists, or IDLE if neither.

Mode Detection Logic

test_id present → TEST_EXECUTION
command present → STANDALONE
Neither → IDLE

Connections
← check_resume
→ rag_retrieval (test)
→ parse_intent (standalone)
→ IDLE (no task)
🔍

rag_retrieval

AI/Analysis Node
Description

Retrieves the test case definition from the RAG (Retrieval-Augmented Generation) database. Fetches test steps, expected outcomes, and verification criteria.

Data Retrieved

Test steps, verification images, expected UI states, pass/fail criteria, and any previously learned solutions.

Connections
← detect_mode
→ check_learned
📚

check_learned

Utility Node
Description

Checks if a learned solution exists for the current test step. If found, skips AI analysis and uses the cached action sequence.

Optimization

Learned solutions significantly speed up repeated test execution by bypassing expensive AI analysis for known scenarios.

Connections
← rag_retrieval
→ direct_execute (has learned)
→ capture_screen (no learned)
📷

capture_screen

Execution Node
Description

Captures a screenshot of the current device screen using ADB screencap. The image is used for AI analysis to understand the current UI state.

Technical Details

Uses adb shell screencap command. Image is stored temporarily and passed to the AI model for visual analysis.

Connections
← check_learned
← increment_retry
← complete_decision (continue)
→ ai_analyze
🤖

ai_analyze

AI/Analysis Node
Description

Uses Claude AI with vision capabilities to analyze the captured screenshot. Identifies UI elements, their coordinates, and current application state.

Analysis Output

Detected elements (buttons, text fields, labels), coordinates, clickable regions, and overall screen context understanding.

Connections
← capture_screen
→ plan_action
💡

plan_action

AI/Analysis Node
Description

AI plans the next action based on the current screen analysis and test step requirements. Determines what ADB command to execute.

Action Types

tap(x, y), swipe(x1, y1, x2, y2), input_text(text), keyevent(code), wait(ms)

Connections
← ai_analyze
→ execute_adb
⚡

direct_execute

Execution Node
Description

Executes a previously learned action sequence without AI analysis. This is the fast path for known test scenarios.

Performance Benefit

Skips capture_screen, ai_analyze, and plan_action nodes, reducing execution time significantly for repeated tests.

Connections
← check_learned
→ execute_adb
💻

execute_adb

Execution Node
Description

Executes the planned ADB command on the connected Android device. This is the core action execution node.

Supported Commands

adb shell input tap x y
adb shell input swipe x1 y1 x2 y2
adb shell input text "..."
adb shell input keyevent CODE

Connections
← plan_action / direct_execute / parse_intent / apply_guidance
→ verify_result
✅

verify_result

Verification Node
Description

Verifies the action result using multiple methods: SSIM image comparison, OCR text verification, and AI visual analysis.

Verification Methods

SSIM: Structural similarity with reference image
OCR: Text presence/absence verification
AI: Visual reasoning for complex states

Connections
← execute_adb
→ next_step (success)
→ increment_retry (failure)
→ wait_human (max retries)
🔄

increment_retry

Utility Node
Description

Increments the retry counter when verification fails. Tracks retry attempts to determine when to escalate to HITL.

Retry Logic

Default max retries: 3. After exceeding, transitions to wait_human for manual intervention.

Connections
← verify_result
→ capture_screen
👋

wait_human

HITL Node
Description

Pauses execution and waits for human intervention. Sets status to WAITING_HITL and persists state for later resumption.

HITL Flow

User reviews failure via dashboard, provides guidance through API, system resumes with apply_guidance node.

Connections
← verify_result (max retry)
→ apply_guidance (after human input)
💡

apply_guidance

HITL Node
Description

Applies human-provided guidance to continue execution. Interprets user instructions and translates them into executable actions.

Guidance Types

Direct coordinates, element descriptions, alternative approaches, skip step, or abort test.

Connections
← wait_human / check_resume
→ execute_adb
💬

parse_intent

AI/Analysis Node
Description

Parses natural language commands in standalone mode. Converts user intent into executable ADB actions.

Example Commands

"Open Settings" → Launch settings app
"Scroll down" → Swipe gesture
"Type hello" → Text input

Connections
← detect_mode
→ execute_adb
➡

next_step

Utility Node
Description

Advances to the next test step after successful verification. Checks if all steps are complete or if there are more to execute.

State Update

Increments current_step, resets retry counter, updates progress metrics.

Connections
← verify_result
→ capture_screen (continue)
→ save_learned (complete)
💾

save_learned

AI/Analysis Node
Description

Saves the successful action sequence as a learned solution to the RAG database for future use.

Data Saved

Screen state signature, action sequence, verification criteria, success metrics.

Connections
← next_step (complete)
→ log_results
📋

log_results

Utility Node
Description

Logs the final execution results including pass/fail status, timing metrics, and any errors encountered.

Output

Execution report saved to test history, metrics updated in dashboard, notification sent if configured.

Connections
← save_learned
→ END
◼

IDLE

End State
Description

Idle state when no test or command is provided. The graph exits without performing any actions.

Connections
← detect_mode
→ END
■

END

Termination
Description

The termination point of the LangGraph workflow. All execution paths eventually converge here.

Final State

Workflow state is persisted, resources are released, and the execution is marked complete.

Connections
← log_results / IDLE
